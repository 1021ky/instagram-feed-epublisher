# ADR-0001: Instagram OAuth ログイン時の再認証制御とログアウト通知の設計

- **ステータス**: Accepted
- **日付**: 2026-11-21
- **関連 Issue**: [#100](https://github.com/1021ky/instagram-feed-epublisher/issues/100)

## 1. 背景 (Context)

本アプリは Better Auth の JWE Cookie Cache を利用し、サーバー側にユーザーデータやトークンを保有しない完全ステートレス構成で運用しています。
初期実装では `webapp/src/lib/auth.ts` の `authorizationUrlParams` に `force_authentication: "1"` が設定されていたため、初回ログインでなくてもログインのたびに Instagram 側で再認証フローが強制される状態となっていました。

Meta 公式ドキュメント（[Business Login for Instagram](https://developers.facebook.com/docs/instagram-platform/instagram-api-with-instagram-login/business-login)）および実機確認の結果、以下の仕様と制約が判明しました。

1. `https://www.instagram.com/oauth/authorize` において、再認証を強制する公式パラメータは `force_reauth`（Boolean、デフォルト `false`。旧来・内部パラメータ `force_authentication=1` 相当）である。
2. `force_reauth` を指定しない（デフォルト `false`）ことで、アプリ側が毎回 ID/パスワード再入力を強制する挙動は停止できる。
3. 一方で、Instagram OAuth には OpenID Connect (OIDC) の `prompt=none`（同意画面の完全スキップ）、`prompt=select_account`（アカウント選択画面の表示）、RP-Initiated Logout（アプリ側からの IdP ログアウト）に相当する公式パラメータ・API は存在せず、2回目以降のログインでも Meta 側の継続共有確認画面（`/consent/?flow=ig_biz_login_oauth`）自体は Meta 仕様として表示される。

## 2. 検討した選択肢 (Options Considered)

| 案                                                                 | 概要                                                                                                                                               | メリット                                                                                                                                     | デメリット                                                                                                                                                                                   |
| :----------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------- | :------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **案1-B: 通常 SSO 一本化 ＋ ログアウト直後のシンプル通知（採用）** | `force_authentication: "1"` を削除して通常ログインに一本化し、ログアウト直後のみ `@<username> からログアウトしました` の `StatusBanner` を表示する | 画面の認知負荷が最小で、2つのログインボタンによる混乱や技術的仕組みの説明ノイズがない。複数アカウント切替は Instagram 側の標準フローに委ねる | アプリ画面上から直接別アカウント入力画面を強制表示する導線はない                                                                                                                             |
| **案2: 通常 SSO ＋「別のアカウントでログイン」2導線型**            | 通常ログインに加え、`force_reauth=true` を付与する「別のアカウントでログイン」導線を併設する                                                       | アプリ UI から直接再認証画面を出せる                                                                                                         | 実機レビューの結果、「Instagramでログイン」と「別のアカウントでログイン」の対比が直感的に分かりにくく、現在 Instagram でログイン中のアカウント名を技術的に保証できないため UX 上の混乱を招く |
| **案3: 都度再認証型**                                              | 現状通り常に `force_reauth=true` 相当を維持する                                                                                                    | ログアウト後の別アカウントログインや共有端末での安全性が高い                                                                                 | 通常ログインでも毎回 ID/パスワード再入力が強制され、Issue #100 の課題が解消しない                                                                                                            |

## 3. 決定 (Decision)

**案1-B（通常 SSO 一本化 ＋ ログアウト直後のシンプル通知）** を採用します。

### 採用理由

- 当初は OAuth 2.0 ベストプラクティスに沿った **案2（2導線型）** も実装・検証しましたが、実機レビューの結果、以下の理由から **案1-B** が本アプリのユーザー体験に最も適していると判断しました。
  1. 本アプリからはブラウザ上の `instagram.com` で現在ログイン中のアカウント名をリアルタイム取得できないため、「別のアカウントでログイン」の対となる「〇〇として再ログイン」を保証できず、2つのログイン導線が並ぶと利用者が迷う。
  2. 「Instagram のログイン状態はブラウザに維持されています」といったシステム都合の説明文はユーザーのメンタルモデルと合わずノイズになる。
  3. 複数アカウント利用者は Instagram 側でログイン中のアカウントが使われることを理解しているため、ログイン導線をシンプルに一本化し、ログアウト時のみ直前のユーザー名（メモリ保持・端末非保存）を添えて「`FeedsToBook からログアウトしました（@<username>）`」と通知するのが最も明快である。

### 実装方針

1. `webapp/src/lib/auth.ts` の `authorizationUrlParams` から `force_authentication: "1"` を削除する。
2. `webapp/app/page.tsx` および `webapp/src/components/molecules/StatusBanner.tsx` にて、ログアウト直後のみ `FeedsToBook からログアウトしました（@<username>）` の閉じるボタン付き `StatusBanner` を `LoginCard` 直上に表示する（リロードで消えるメモリ保持のみ）。

## 4. 影響・トレードオフ (Consequences)

- **共有端末・複数アカウント利用時**: 通常の「Instagramでログイン」ではブラウザに残っている Instagram セッションが利用されるため、別アカウントへ切り替えたい場合はユーザー側で Instagram サイトのアカウント切り替えを行う運用とします。
- **Meta 側の同意画面仕様への依存**: `force_authentication` を外しても、2回目以降のログインで Instagram 側（`/consent/?flow=ig_biz_login_oauth`）の継続共有確認画面が表示される挙動は Meta 側のサーバー仕様であり、ステートレス構成のまま完全にスキップすることはできません。
