# ドキュメント更新ポリシー (Documentation Policy)

本リポジトリにおけるドキュメントおよびダイアグラムの管理方針・品質基準です。
人間（開発者・コントリビューター）および AI エージェントの双方が遵守すべき共通ルールを定めます。

---

## 1. ドキュメントの配置と役割分担

| ファイル / ディレクトリ | 役割                             | 記載内容                                                                                                                             |
| :---------------------- | :------------------------------- | :----------------------------------------------------------------------------------------------------------------------------------- |
| **ルート `README.md`**  | **リポジトリ全体の総合ポータル** | プロジェクト概要、管理対象、ディレクトリ構成、前提環境、セットアップ・開発手順、設計書へのリンク、ロードマップ                       |
| **`webapp/README.md`**  | **Web アプリ固有リファレンス**   | `webapp/` 配下の開発コマンド一覧、ディレクトリ構成、E2E テストの現状                                                                 |
| **`designdoc/`**        | **設計仕様書 & Mermaid 図面**    | 詳細設計書（`designDoc.md`）、ユーザーフロー図（`flowchart LR.mmd`）、ER図（`erDiagram.mmd`）、シーケンス図（`sequenceDiagram.mmd`） |
| **`docs/`**             | **プロジェクト規約・運用ガイド** | ドキュメント更新ポリシーなどの共通ガイドライン                                                                                       |

---

## 2. コード変更時のドキュメント同時更新原則

機能追加やリファクタリング等の変更を行う際は、**コードと同時にドキュメントも更新する** ことを必須とします。

1. **仕様変更・機能追加時**:
   - `designdoc/designDoc.md` の要件・機能一覧・モジュール構成を更新する。
   - 外部仕様に関わる場合は ルート `README.md` も更新する。
2. **データフロー・API 変更時**:
   - 認証や API 通信シーケンスの変更は `designdoc/sequenceDiagram.mmd` を更新する。
   - ユーザー操作フローの変更は `designdoc/flowchart LR.mmd` を更新する。
3. **データモデル変更時**:
   - テーブルやセッション構造の変更は `designdoc/erDiagram.mmd` を更新する。
4. **環境変数・前提ツールの追加・変更時**:
   - ルート `README.md` の「前提環境」および「環境変数の設定」テーブルを更新する。
5. **ディレクトリ構成の変更時**:
   - ルート `README.md` および `webapp/README.md` のディレクトリツリーを更新する。

## 3. 品質基準と自動検証

ドキュメントおよび図面は、常に以下の品質基準（警告・エラーゼロ）を満たす必要があります。

### A. Markdown ファイル (`*.md`)

- **フォーマット**: `oxfmt` による一貫したスタイル整形
- **静的解析 (Lint)**: `markdownlint-cli2` による構文チェック（警告・エラー 0 件）
  - 見出し（MD022）やリスト（MD032）の前後に適切な空行を配置すること。
  - 行長（MD013）およびインラインHTML（MD033）はプロジェクト設定（`.markdownlint-cli2.jsonc`）で緩和されています。

### B. Mermaid 図面 (`*.mmd`)

- **構文・変換検証**: `@mermaid-js/mermaid-cli`（`mmdc` コマンド）を用いてパースおよび画像変換が正常に成功すること。
- 変換検証コマンド: `pnpm check:mermaid`

---

## 4. 実行コマンド一覧

プロジェクトルートで以下のコマンドを実行できます：

```bash
# Markdown のリントチェック
pnpm lint:md

# Markdown のリント自動修正
pnpm lint:md:fix

# Markdown / ソースコードのフォーマット
pnpm format

# フォーマットチェックのみ
pnpm format:check

# Mermaid 図面の変換チェック
pnpm check:mermaid
```

---

## 5. CI / コミットフックによる品質保証

- **Pre-commit Hooks (Husky + lint-staged)**:
  コミット時にステージされた `.md` ファイルに対して `oxfmt` と `markdownlint-cli2 --fix` が自動実行され、`.mmd` ファイルに対して `check-mermaid.mjs` による検証が自動実行されます。
- **GitHub Actions CI (`webapp-ci.yml`)**:
  Pull Request および `main` への push 時に、Markdown リント・フォーマットチェックおよび Mermaid 構文検証が必須チェックとして自動実行されます。
